# 现场代码练习说明

“03_代码练习”包含8个独立C99小程序。每个文件有所需标准头文件、示例实现和带assert断言的main；先遮住实现自己写，再运行测试，比只阅读答案更有效。

| 文件 | 训练重点 | 边界或性质验证 |
| --- | --- | --- |
| 01_ring.c | 有界FIFO、留空一格、失败语义 | 空、满、FIFO顺序、10000次索引循环 |
| 02_parser.c | 分片输入、状态机、失败不提交 | 空帧、64字节帧、坏长度、坏校验、连续帧 |
| 03_tick.c | 无符号时间差与回绕范围 | 跨零点、恰好到期、提前一tick及多组起点 |
| 04_parse.c | 十进制严格解析和前置溢出检查 | uint32上限、非法字符、嵌入NUL、10000次往返 |
| 05_endian.c | 对齐无关的字节序装配 | 非对齐偏移、SIZE_MAX、失败不改数据、100000次往返 |
| 06_debounce.c | 候选与稳定状态、非阻塞边沿 | 抖动、长按、释放、上电已按下、时间回绕 |
| 07_pool.c | 固定资源与世代句柄 | 满池、重复释放、旧句柄、非法槽与世代耗尽 |
| 08_average.c | O(1)更新与累加范围证明 | 正负极限、启动窗口、10000个样本对照朴素算法 |

## 用自己的工具链运行

示例（已安装GCC或Clang的开发环境）：

```sh
cc -std=c99 -Wall -Wextra -Werror 01_ring.c -o ring_test
./ring_test
```

对其他文件分别编译运行，不要把8个有main的文件一次链接在一起。Windows工具链生成的程序通常带.exe后缀。头文件、库和命令细节以你的工具链为准。

本次交付在Windows上实际使用TinyCC 0.9.27，以C99、-Wall、-Werror编译这8份源码并运行全部断言。测试工具只在制作电脑上使用，U盘不包含编译器和预编译可执行文件。该验证不等于证明所有编译器、位宽和优化组合都正确。

## 重要前提

- 示例均为单线程或由调用方完成外部保护的模型，不是可以直接共享给ISR和任务的无锁实现。
- 示例没有访问真实硬件，也未在MCU执行；中断、DMA、缓存、特殊地址空间须另行验证。
- 各函数在注释中说明指针与初始化契约。调用方提供错误的内存对象范围，单靠“指针+长度”接口不能自动修复。
- parser使用教学用异或校验，不是CRC或安全认证；未实现生产协议的全部同步、重传与超时。
- tick差值法依赖单调计数器和跨度范围；丢失完整多圈信息无法通过强制类型转换恢复。
- pool只管理字节块句柄，不承诺任意对象对齐，也不提供跨线程保护。句柄仅对原池及其当前生命周期有效，不能跨池使用；重新初始化池前必须停止使用所有旧句柄。
- 主机支持时，可另外启用ASan/UBSan运行；本次交付记录不会把未执行的这些工具说成已测试。

## 面试时的顺序

先确认输入范围、失败语义、并发环境和资源限制，再写最小实现。写完马上给出空输入、最大值、回绕、输出是否被部分修改等测试。若面试官增加ISR、多生产者或断电条件，先指出原证明失效在哪里，再修改设计。
