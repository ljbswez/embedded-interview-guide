这是可调整的复习建议，不按工作年限机械划分水平。MCU与Linux都准备时，先补共同基础，再沿两条路线深入。每日建议60—120分钟：阅读8题、脱稿口述3题、做1个验证，并记录今天仍不确定的边界。

## 每道题的五步口述

1. **先说前提**：C还是C++，MCU还是Linux，任务还是ISR，单核还是多核，有无缓存，具体版本是否已知。
2. **先给结论**：用两三句话回答原问，不先堆一长串名词。
3. **解释机制**：画数据流或时间线，说清读写顺序、阻塞点和状态变化。
4. **补一个例子**：优先使用自己的真实项目；没有实际做过就明确说这是分析方案。
5. **收在验证**：用哪份手册、哪种工具、哪些边界测试确认，哪些地方还存在不确定性。

## 上场前速查：必须能区分的成对概念

- volatile / atomic / mutex / memory barrier：可观察访问、原子性、互斥、排序是不同问题。
- 指针生命周期 / 对象生命周期 / 所有权：有地址不代表对象仍有效，有引用不代表你负责释放。
- 单线程正确 / 任务与ISR共享正确 / 多核正确：逐层增加的约束要逐层证明。
- Cache clean / invalidate / CPU屏障：数据所在位置、可见性与顺序不能互相替代。
- RTOS就绪 / 运行 / 阻塞：高优先级任务阻塞时不抢CPU；忙等与等待事件不同。
- 信号量 / 互斥锁 / 队列 / 通知：事件计数、资源所有权、传数据及具体内核机制要分清。
- 一次接收 / 一帧协议 / 一次业务成功：链路交付、帧校验和应用处理是三个层次。
- CRC / 哈希 / MAC或签名：随机错误检测、摘要与真实性边界不同。
- A/B分区 / 有效性校验 / 试运行确认 / 防回滚：分区结构本身不等于完整可靠升级。
- CPU虚拟地址 / CPU物理地址 / DMA地址：地址域不能随意强转互换。
- 进程退出 / 文件描述符关闭 / 设备解绑：资源与异步工作要按各自生命周期处理。
- 平均时延 / 最坏时延 / 截止期：平均数好看不代表实时要求成立。

每一条的详细原理与追问都在相应讲义中。这里的短句只用于提醒，不代替上下文和具体平台说明。

## 面试前一天

- 准备一张项目架构图、一张关键时序图、一份脱敏的故障复盘，写清本人职责。
- 只保留能解释来源和测量方法的指标；示例数据不要写成自己的实测成绩。
- 把所有“我优化了”“我提高了稳定性”改成具体约束、改变、证据和剩余限制。
- 复习最容易混淆的题，练习一句话说明“当前条件下我能确定什么，下一步怎么验证”。
- 看清岗位侧重：MCU关注时序和资源；Linux关注上下文、生命周期及系统诊断；两者都需要语言基础和可靠交付。

## 可以向面试官反问

1. 产品的主要实时性、功耗、成本和现场维护约束分别是什么？
2. 团队的软件与硬件接口、驱动与应用责任边界怎样划分？
3. 当前最需要解决的是新功能、性能、可靠性、量产还是已有平台维护？
4. 代码评审、硬件回归、发布回滚和线上故障收集怎么进行？
5. 这个岗位前三个月预期交付什么，如何判断完成质量？

优先选择与岗位和前面讨论有关的问题，不要一次照单念完。
